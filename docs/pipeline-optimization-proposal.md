# ClipFlow 子代理管线优化方案（v3 定稿）

> 版本：v3（2026-08-07）· 定稿：自由组合 + 强制底限 + 动态升级 + 审计
> 依据：侧线分析 + 主代理跑完 Phase 3/4/5 的第一手实证 + 多轮讨论
> 目标：骨架不动（探索→设计→实现→独立验收），成本随任务规模自适应；决策进 git、产物不堆积、中断可恢复、质量有硬底限

---

## 0. 原则（不可破）

1. 骨架不动：探索先行、决策留痕、独立验收、上下文隔离。
2. 代码阶段串行（防冲突是刻意设计）。
3. 管线是给「重要且复杂」的活用，不是给所有活用。
4. 不把 §6 无条件同步给 CLAUDE.md（MiMo 长流程未验证）。

---

## 0.5 核心框架（本次定稿的核心改动）

**从「强制三档」升级为「规则约束下的自由组合」**：

- **阶段池**：explorer / architect / coder / tester / reviewer / debugger / 主代理直做 —— 主代理按任务任意组合，**向上自由**。
- **参考配方**：保留快速/标准/完整三档作为「默认起点」（拿来即用的菜谱），不是强制捆包。
- **强制底限**：质量底限是**规则**（非偏好），主代理无权绕过 —— 写业务代码必须有独立验证；触红线必须有 architect+reviewer。
- **动态升级**：任何阶段发现超规模立即加阶段，不硬扛。
- **审计**：每任务记录「阶段组合 + 理由 + 报告路径」，子代理报告落盘不可删 → 偷工可被发现。
- **模型无关**：底限是硬规则，不依赖对模型能力的预先判断（换模型不影响正确性）。

---

## 1. 阶段池与参考配方（三档）

| 配方 | 流程 | 适用 |
|------|------|------|
| **快速** | 主代理直做（TDD）→ 可选 tester | 轻量改动；轻功能（单模块、不碰红线）；基础设施/运维；根因已定位的小 bug |
| **标准** | explorer(可并行) → coder → tester | 新功能（多模块/2–3 文件/UI）；普通 bug（根因不完全清晰） |
| **完整** | explorer(可并行) → architect → coder → tester → reviewer | 重大改动（加密/同步/架构/跨 3+ 文件/双端） |

> **自由组合**：上表是参考配方（默认起点）。主代理可按任务实际增减阶段（如纯 bug 用 `debugger→coder→tester`、只读验证用 `tester` 单独跑），**只要满足 §2.1 强制底限即可**。

> **基础设施/运维归快速档**：部署/网络/证书/真机安装等非代码活，主代理直做 + 必要时 tester，不进多阶段管线。

---

## 2. 强制底限 + 初始判定 + 动态升级

### 2.1 强制底限（规则，主代理无权绕过）

```
① 写了业务代码 → 必须有独立验证（tester 报告落盘）；禁止「自写自验」算完成
② 触红线（加密格式/密码派生/token认证/数据库结构/同步去重/跨3+文件/双端/三端平台）
   → 必须有 architect + reviewer
③ 不满足底限 = 任务未完成：必须补阶段，或显式记录风险注记并获用户知晓
④ 基础设施/非代码 → 无强制，主代理直做
```

### 2.2 初始判定（一次性，猜错可升级）

```
任务输入
 ├─ 触红线？ → 完整（不申请）
 ├─ 明确小工程（单文件/文案/配置/文档/基础设施/根因已定位）？ → 快速（不申请）
 ├─ 中等但方向明确（多模块新功能/普通 bug）？ → 标准（不申请）
 └─ 边界模糊 / 成本敏感 → 请示（附 §3 三档预期）
```

### 2.3 动态升级（关键：档位可中途上调）

> 原则：**发现规模/风险超出当前档位，立即升级，不硬扛**。升级不丢工作（checkpoint 已保留进度），只是追加更高保障继续。

**触发信号（任一出现即升级）**：

| 当前档位 | 触发信号 | 升级到 |
|---------|---------|--------|
| 快速 | 侦察/实现中发现触红线、跨 3+ 文件、涉及同步/状态机、需要设计决策 | 标准；触红线直接完整 |
| 快速 | 改动需要独立验证而当前只有自验（涉及历史/加密/跨端副作用） | 标准（补 tester） |
| 标准 | explorer 报告设计风险 / 约束歧义 / 边界未覆盖 | 完整（补 architect + reviewer） |
| 标准 | coder 实现中架构假设不成立、方案有歧义 | 完整（先 architect 定案再继续） |

**升级规则**：
1. **发现即升级，不等做完**；已完成的探索/实现保留，只追加缺失阶段。
2. **快速档开工先做 5 分钟侦察**（读相关文件、找调用点），把误判前移。
3. **升级必须留痕**：成本摘要记录「初始档 → 升级档 → 原因」。
4. **不鼓励反向降级**（高→低），除非明确判大且继续无意义（记录原因）。

## 3. 请示模板（附三档预期）

| 档位 | 流程 | 预计时长 | 质量保障 | 适用 |
|------|------|---------|---------|------|
| 快速 | 主代理直做 → 可选 tester | ~10 分钟 | 单测+自验 | 小改动、风险低 |
| 标准 | explorer → coder → tester | ~30 分钟 | 探索+独立测试 | 中等功能 |
| 完整 | explorer → architect → coder → tester → reviewer | ~60 分钟 | 全链路+终审 | 重大改动 |

---

## 4. 配套治理

1. **决策留档**：验收后主代理把关键决策以「背景-决策-后果」同步进 `docs/decisions/`（进 git）。
2. **产物治理**：`.codex/pipeline/` 按里程碑归档到 `archive/<里程碑>/`；保留最近 1 个里程碑全过程 + 历史摘要。
3. **任务文件瘦身**：阶段任务文件只写「输入路径 + 本阶段增量 + 输出路径」，需求唯一源在 `phaseX-task.md`。
4. **checkpoint**：coder 每完成一个逻辑单元 `git commit` 一次（本工作树/feature 分支），中断从最后 commit 续跑。
5. **explorer 并行**：探索只读，按 server/client/平台 拆并行；写代码阶段保持串行。
6. **握手简化**：文件投递场景要求「先读文件确认已加载」即可，不强制先回「收到任务，开始执行」；消息投递保留握手。
7. **成本摘要**：每轮结束输出一行：档位/组合/代理数/墙钟/产物路径/结论（含 model）。
8. **审计**：子代理报告全部落盘 `.codex/pipeline/`，主代理不可删；主代理的「阶段组合 + 理由」记录可查。

## 5. 与现状对比

| 维度 | 现状 | 优化后 |
|------|------|--------|
| 路由 | 轻量直做 / Bug 4 连 / 新功能 5 连 / 重大 5+ | 自由组合 + 参考配方（快速/标准/完整）|
| 基础设施活 | 无路由覆盖，被当代码管线或临时直做 | 明确归快速档 |
| 探索 | 串行 1 个 explorer | 可并行拆分 |
| 质量约束 | 靠「固定全流程」保证 | 靠「强制底限规则 + 审计」保证（更省、更可查）|
| 任务文件 | 每阶段复述需求 | 只写输入+增量+输出 |
| 握手 | 每阶段强制先回「收到任务」 | 文件投递跳过 |
| 中断恢复 | 靠运气（丢过工作） | coder 按单元 commit |
| 决策留档 | 只躺 gitignored pipeline | 同步 docs/decisions/ |
| 产物 | 61 个文件无清理 | 按里程碑归档 |
| 成本可见性 | 无 | 每轮成本摘要 |
| 档位判定 | 固定路由 / 主代理自由裁量 | 初始判定 + 动态升级 + 边界请示 + 审计 |

## 6. 提升评估（自审结论：是否真有提升）

### 6.1 确定提升
| 项 | 依据 |
|----|------|
| 基础设施归快速档 | 本轮 70% 时间耗在隧道/证书排障，这类活走多阶段是错配 |
| coder checkpoint | 本轮技术债 coder 中断丢工作重做；commit 断点续跑直接消除 |
| 决策留档 docs/ | 决策是本项目最值钱产物，此前全丢在 gitignored pipeline |
| 强制底限 + 审计 | 质量约束从「依赖固定流程」转为「规则 + 可见性」，更省且防偷工 |

### 6.2 边际提升
| 项 | 说明 |
|----|------|
| 任务文件瘦身 / 握手简化 / 成本摘要 | 每轮省 10–20% 编排开销 |
| explorer 并行 | 多端探索墙钟减半 |
| 快速/标准档裁剪 | 中小任务省 40–60% 墙钟与 token；大任务无收益（仍走完整）|

### 6.3 有风险但可控
| 风险 | 控制 |
|------|------|
| 裁剪放走设计问题 | 强制底限 + 动态升级（触险即升）+ 审计 + 复盘 |
| 主代理档位误判 / 偷工 | 底限是规则非偏好；组合留痕可审计；边界模糊必请示 |
| 标准档缺 architect 漏设计缺口 | explorer 触险即升完整；复盘发现漏判则收紧判定 |

### 6.4 总判断
> **是真提升，但有边界。** 提升集中在「基础设施直做 + 中小任务裁剪 + 强制底限/审计治理」；大任务维持原质量不变。
> 代价是主代理的档位判断力成为关键依赖——由「底限规则 + 审计 + 成本摘要 + 复盘」持续监控。
> **值得做，但必须带升级路径与审计一起上**，否则裁剪会变成放水。

---

## 7. 落地与验证（简化试点）

不做造任务对照实验，直接**采纳 + 记录 + 复盘**：
1. 落地本方案（改 AGENTS.md + 建 docs/decisions/ + 归档脚本 + 任务书模板）→ 快速档直做。
2. 接下来 2–3 个真实任务按此跑，每轮记成本摘要。
3. 复盘点：标准档任务若漏了本应被抓的问题 → 收紧判定；频繁升级 → 调配方。
4. 输出复盘报告，决定是否调标准。

---

## 8. 明确不做

1. 不推翻探索→设计→实现→验收骨架。
2. 代码阶段不做无脑并行。
3. 不把 §6 无条件同步 CLAUDE.md（除非试点验证 MiMo 可跑通）。
4. 不给轻活上重管线。
5. 不做运行时模型自我能力判读（不可靠）。
6. 不做造任务的对照实验。
